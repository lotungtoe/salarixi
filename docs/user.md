# Начало

## Для чего предназначен клиент

- **Стресс-тесты:** проверка серверов на мощность.
- **Автоматизация:** автоматическое выполнение простых задач.
- **Тестирование:** проверка анти-бот и анти-чит систем.
- **Фарминг (PvE):** масштабные авто-фермы.

# Раздел "Главная"

Раздел _Главная_ — это стартовая страница. Здесь задаётся подключение к серверу и запускаются или останавливаются боты.

## Поля

- `Адрес сервера`: IP или домен с портом, например: `mc.server.com`, `127.0.0.1:25565`. Если не указывать порт, будет установлен 25565 по умолчанию.
- `Кол-во ботов`: Количество запускаемых ботов.
- `Задержка подключений`: Интервал в миллисекундах между подключениями ботов. Рекомендуется ставить значения от `4000` до `7000`. При слишком мелкой задержке твой процессор будет испытывать очень большую нагрузку.

## Кнопки

- **Запустить**: Запуск ботов с текущими настройками. После запуска настройки невозможно изменить (можно менять значение, но на текущем процессе это не отобразится).
- **Остановить**: Отключение всех ботов, очистка данных, выключение служб (график, мониторинг, радар).
- **Генерация**: Случайная подстановка значений в поля (кол-во, задержка).
- **Очистить**: Сброс всех полей на странице.

# Раздел "Настройки"

Данный раздел содержит в себе основную часть настроек и контролирует состояния тех или иных особенностей запуска.

## Основные настройки

**Важно:** При включённой фиче **Использовать аккаунты** эти настройки не будут доступны, ты сможешь изменить их для каждого аккаунта в разделе _Аккаунты_.

### Никнейм

- **Легитный**: Никнейм генерируется на основе реального имени игрока, выбранного при помощи псевдослучайности из списка (всего ~110 никнеймов), и небольшой модификации выбранного имени.
- **Случайный**: Никнейм генерируется на основе простого шаблона, выбранного при помощи псевдослучайности из списка.
- **Кастомный**: Ты сам задаёшь шаблон для псевдослучайной генерации никнейма. Допустимые теги: `#n` (3 случайные цифры от 0 до 9 включительно), `#l` (3 случайные литеры любого регистра), `#m` (3 случайных символа, состоящих из цифр от 0 до 9 включительно и литер любого регистра). Есть ещё тег `#s`, но он включает в себя специальные символы, поэтому для генерации никнеймов он непригоден. Пример шаблонов: `player_#n#n` -> `player_627496`, `#l#n` -> `wKd815`.

### Пароль

- **Без пароля**: Всё просто, боты не будут использовать и хранить пароль.
- **Легитный**: Аналогично никнейму, но список паролей меньше (всего ~10 паролей).
- **Случайный**: Аналогично никнейму.
- **Кастомный**: Аналогично никнейму. Здесь уже можно спокойно использовать тег `#s`, так как пароли со специальными символами разрешены на многих серверах.

### Электронная почта

- **Без почты**: Вновь всё просто, боты не будут использовать и хранить почту.
- **Случайный**: Генерируется псевдослучайная, скорее всего несуществующая почта. Генерация опирается на такие почты как: gmail.com, proton.me, yandex.ru, mail.ru.

## Настройки регистрации

Данный раздел будет доступен после включения фичи **Auto-Register**.

### Режим

- **Обычный**: Боты регистрируются через псевдослучайную задержку, сгенерированную с учётом указанных границ (максимальная и минимальная задержка в миллисекундах). Это подходит тогда, когда у ботов стабильное соединение, известно точное время процессов, которые проходят до момента регистрации.
- **Триггер**: Изначально боты ожидают сообщение в чате, которое содержит указанное вами ключевое слово (допустим, `зарегистрируйтесь`, `register`), после чего мгновенно отправляют сообщение в чат. Подходит при нестабильном подключении, в любых ситуациях, где неизвестно время начала регистрации.

### Команда

Команда регистрации. Например: `/register`, `/reg`.

Если команда не будет указана, процесс регистрации будет прерван.

### Шаблон

Шаблон — это самая важная часть настроек регистрации. Именно он решает как будет выглядеть финальное сообщение.

Допустимые ключевые слова:

- `$cmd`: Заменяется на команду регистрации. Пример: (скажем, выше мы указали команду `/register`) `$cmd qwe123` -> `/register qwe123`.
- `$pass`: Заменяется на пароль, который ты указывал в основных настройках (если включена фича `Использовать аккаунты`, то берётся пароль, заданный для текущего аккаунта). Пример: (допустим, выше мы указали пароль `qwe123`) `$cmd $pass $pass` -> `/register qwe123 qwe123`.
- `$email`: Заменяется на электронную почту, которую ты указывал в основных настройках (вновь исключение, если включена фича **Использовать аккаунты**, то берётся почта, заданная для текущего аккаунта). Пример: `$cmd $pass $email` -> `/register qwe123 jieruy74u@proton.me`.

Если оставить шаблон пустым, будет использован `$cmd $pass`.

## Настройки логина

Данный раздел будет доступен после включения фичи **Auto-Login**.

Всё аналогично настройкам регистрации, исключений нету.

## Настройки переподключения

Данный раздел будет доступен после включения фичи **Auto-Rejoin**.

### Задержка переподключения

В этом поле указывается задержка в миллисекундах, которая будет использована перед повторным подключением. Рекомендуется указывать задержку от `3000` до `8000`.

## Настройки мониторинга

### Частота обновлений

Здесь ты указываешь интервал в миллисекундах между обновлениями данных мониторинга. Рекомендуется ставить значения от `1000` до `5000`.
 
### Длина истории чата

В данном поле указывается максимальная длина видимого чата ботов в мониторинге. При достижении лимита самые старые сообщения будут удалены из истории чата бота. Рекомендуется ставить значения от `25` до `80`. Если мониторинг чата тебя не интересует, можно поставить значение `0`.

## Дополнительные настройки

- `Дистанция прогрузки`: Дальность прорисовки чанков. Рекомендуется ставить значения от `8` до `16`.
- `Ведущая рука`: Ведущая рука у ботов. Доступно два значение: `left` и `right`. Если оставить это поле пустым, для каждого бота будет выбрано псевдослучайное значение.

## Фичи (особенности)

- **Использовать Auto-Register**: При включении боты будут автоматически регистрироваться.
- **Использовать Auto-Login**: При включении боты будут автоматически логиниться.
- **Использовать Duble-Auth**: Требует включенные опции: **Auto-Register**, **Auto-Login**. При включении боты, пройдя процесс регистрации, не будут изменять состояние `login`, тем самым они дальше будут ожидать процесса логина.
- **Использовать Auto-Rejoin**: При включении боты будут автоматически переподключаться к серверу, если их кикнуло.
- **Использовать Chat-Signing**: При включении боты будут автоматически выполнять операцию Chat-Signing.
- **Использовать Auto-Respawn**: При включении боты будут моментально респавнится при событии смерти.
- **Использовать Accept-RP**: При включении боты будут принимать и обрабатывать все пакеты с ресурс паками.
- **Использовать Pathfinder**: При включении боты смогут использовать функции pathfinder'а.
- **Использовать Auto-Script**: При включении и получении события о спавне для каждого бота отдельно будет запускаться написанный тобой ранее сценарий.
- **Использовать прокси**: При включении боты будут использовать указанные тобой прокси (настраивать в разделе _Прокси_).
- **Использовать анти-капчу**: При включении боты будут использовать анти-капчу (настраивать в разделе _Анти-Капча_).
- **Использовать вебхук**: При включении некоторые данные будут отправляться (настраивать в разделе _Вебхук_).
- **Использовать аккаунты**: При включении на панели управления появится раздел _Аккаунты_, при запуске будут использоваться аккаунты из списка.

# Раздел "Аккаунты"

В этом разделе ты можешь управлять аккаунтами ботов — добавлять, удалять, импортировать...

## Генерация аккаунтов

Чтобы сгенерировать аккаунты, тебе нужно указать число генерируемых аккаунтов (от 1 до 200) и шаблон для генерации юзернеймов.

Шаблон может содержать следующие теги:

- `#n`: 3 случайные цифры (от 0 до 9 включительно).
- `#l`: 3 случайные литеры (любого регистра).
- `#m`: Комбинация `#n` и `#l`.
- `#i`: Текущий индекс юзернейма.

Пример шаблона: `bot_#m` -> `bot_m3K`, `bot_i35`, `bot_GtU`...

## Дополнительно

Если тебе нужно задать сразу нескольким аккаунтам одинаковое значение чего-либо, можно выделить нужные аккаунты, нажав на флаг рядом с их юзернеймами, и после нажать на кнопку редактировать все выделенные аккаунты (в правом верхнем углу).

Если тебе нужно выделить сразу все аккаунты, или наоборот убрать все выбранные аккаунты, можно использовать клавишу `Esc` (escape).

# Раздел "Прокси"

## Список прокси

Прокси вводятся в текстовое поле, по одному на строку. Для SOCKS5 формат: `ip:port`, `socks5://ip:port`, `username:password@ip:port`, `socks5://username:password@ip:port`.

Кнопка **Очистить список** удаляет все записи.

## Сборщик прокси

Сборщик прокси — специальный инструмент, который позволяет автоматически собирать прокси с публичных ресурсов. Важно понимать, что он не проверяет прокси на работоспособность.

У сборщика есть настройки: алгоритм, страна, количество, порт.

### Алгоритм

Эта опция отвечает за то, какие ресурсы будет использовать сборщик, это прямо влияет на скорость сборки, количество и качество прокси.

Доступно всего 3 алгоритма:

- **Trusted**: Алгоритм для сборка прокси с публичных сервисов, которые предоставляют стабильный API и дополнительную информацию про прокси (именно из-за этого только с этим алгоритмом можно применять фильтр по стране). Поиск с этим алгоритмом обычно занимает ~6 секунд, без ограничений находит ~500 прокси.
- **Untrusted**: Алгоритм, предназначенный для сбора прокси с недоверенных ресурсов (какие-то публичные списки, репозитории с прокси и т.д.). Поиск с этим алгоритмом обычно так же занимает ~6 секунд, без ограничений находит 50,000 прокси (больше нельзя, системное ограничение клиента).
- **Mixed**: Из названия понятно что алгоритм совмещает в себе 2 предыдущих. Поиск с этим алгоритмом может занимать ~8 секунд, без ограничений находит 50,000 (вновь ограничение, ради интереса: если не учитывать системное ограничение, этот алгоритм может находить аж до 430,000 прокси).

### Прочее

Ты можешь включать фильтр по странам и порту, это может облегчить поиск определённых прокси.

# Раздел "Анти-Капча"

В этом разделе ты можешь настроить работу анти-капчи перед запуском. В момент активного процесса сюда будут приходить капчи ботов (если режим решения ручной).

## Что за типы?

- **Web**: Бот будет ловить ссылку из чата по указанному тобой регулярному выражению и обязательной части ссылки, после отправлять ссылку на капчу в раздел _Анти-Капча_, которую можно будет открыть, нажав на кнопку **Решить капчу**.
- **Map (Inventory)**: Бот будет ожидать появления предмета FilledMap (заполненная карта) в инвентаре, после чего создаст изображение капчи и отправит в раздел _Анти-Капча_, решить эту капчу можно там же нажав на кнопку **Решить капчу**.
- **Map (Frame)**: Бот будет ожидать появления сущностей ItemFrame / GlowItemFrame и собирать из них единое изображение до того, как не закончится лимит (колонны * ряды), далее всё аналогично **Map (Inventory)**.

## Настройки Web

- **Регулярное выражение**: Здесь ты указываешь регулярное выражение, при помощи которого будут ловиться ссылки на капчу из чата. По умолчанию используется `https?://[^\s]+`.
- **Обязательная часть ссылки**: Фильтр пойманных ссылок. Если ссылка содержит указанную часть, она проходит, иначе нет. Значения по умолчанию здесь нету.

## Настройки Map

### Общие

- **Режим**: Всё просто, ручное решение капчи или автоматическое.
- **API ключ**: Если используется автоматическое решение ты должен указать свой API ключ от RuCaptcha (или же 2Captcha).

### Подтип Inventory

Здесь отсутствуют уникальные настройки.

### Подтип Frame

**Важно:** Подтип Frame не поддерживает капчи динамического размера.

- **Количество коллон**: Максимальное количество частей капчи, расположенных слева направо.
- **Количество рядов**: Максимальное количество частей капчи, расположенных сверху в низ.

# Рездел "Сценарий"

Здесь ты можешь писать свои сценарии для ботов на Rust, который будет выполняться в оболочке Rhai (документацию и примеры можно найти на https://github.com/rhaiscript/rhai).

**Важно:** Оболочка **Rhai** (то что выполняет твой сценарий) не поддерживает некоторые концепции языка Rust, из-за чего их использование напрямую невозможно. Например: Нельзя использовать `async/.await`, нельзя использовать `_` в качестве названия переменной.

## Доступные функции

Системные функции:

- `sleep(delay: u64)`: Остановка выполнения сценари на время (в секундах).
- `print(str: &str)`: Печать информации в текущий терминал.
- `log(text: &str, class: &str)`: Логгирование информации в журнал клиента.
- `message(name: &str, content: &str)`: Отправка уведомления в клиент.
- `webhook(content: &str)`: Отправка вебхука по ранее указанной ссылке.

Простые функции:

- `chat(mu: &str, message: &str)`: Отправка сообщения в чат от указанного бота(ов).
- `jump(mu: &str)`: Одноразовый прыжок.
- `swing_arm(mu: &str)`: Махнуть рукой.

Основные функции-геттеры:

- `active_bots_count() -> i64`: Получение количества активных ботов.
- `get_bot_id(mu: &str) -> i64`: Получение Entity ID указанного бота.
- `get_bot_ping(mu: &str) -> i64`: Получение пинга указанного бота.
- `get_bot_feet_pos(mu: &str) -> Position`: Получение позиции ног указанного бота.
- `get_bot_eye_pos(mu: &str) -> Position`: Получение позиции глаз указанного бота.
- `get_bot_health(mu: &str) -> f64`: Получение здоровья указанного бота.
- `get_bot_satiety(mu: &str) -> i64`: Получение сытости указанного бота.
- `get_bot_profile(mu: &str) -> Profile`: Получение профиля указанного бота.
- `bot_is_workable(mu: &str) -> bool`: Получение состояния работоспособности указанного бота.

Основные функции-сеттеры:

- `set_jumping(mu: &str, state: bool)`: Установка состояния jumping.
- `set_crouching(mu: &str, state: bool)`: Установка состояния crouching.
- `set_velocity(mu: &str, axis: &str, velocity: f64)`: Установка скорости по определённой оси.
- `set_on_ground(mu: &str, on_ground: bool)`: Установка значения для on_ground.
- `set_old_position(mu: &str, x: f64, y: f64, z: f64)`: Установка значения для old_position.
- `set_no_jump_delay(mu: &str, delay: i64)`: Установка значения для no_jump_delay.
- `set_was_touching_water(mu: &str, state: bool)`: Установка значения для was_touching_water.
- `set_has_impulse(mu: &str, state: bool)`: Установка значения для has_impulse.

Функции, отвечающие за различные действия:

- `start_walking(mu: &str, direction: &str)`: Ходьба по указанному направлению.
- `start_sprinting(mu: &str, direction: &str)`: Спринт по указанному направлению.
- `start_pathfinder(mu: &str, x: i64, z: i64)`: Ходьба на укзанные координаты (pathfinder).
- `stop_move(mu: &str)`: Остановка движения (walk && sprint).
- `stop_pathfinder(mu: &str)`: Отсановка задач pathfinder.
- `place_block(mu: &str, x: i64, y: i64, z: i64)`: Установка блока на указанных координатах.
- `look_at(mu: &str, x: f64, y: f64, z: f64)`: Поворот на укзанные координаты.
- `look_at_block(mu: &str, x: f64, y: f64, z: f64)`: Поворот на блок с учётом его центра.
- `drop_selected_item(mu: &str, lock: bool)`: Выбросить предмет, лежащий в руке.
- `inv_click(mu: &str, slot: i64, mode: &str, lock: bool)`: Кликнуть определённым образом на указанный слот. Доступные режимы: `left`, `right`, `shift`, `drop`, `drop-all`.
- `inv_click_on(mu: &str, name: &str, mode: &str, lock: bool)`: Кликнуть определённым образом на предмет с указанным именем.
- `set_selected_slot(mu: &str, slot: i64)`: установить выбранный слот в хотбаре.
- `attack(mu: &str, target: &str, distance: f64, look_at_target: bool)`: Атака определённой ближайшей сущности. Аргумент `target` может иметь значения: any (любая сущность), player, monster, animal, vehicle.
- `start_use_item(mu: &str, hand: &str)`: Начать использование предмета в указанной руке (mainhand / offhand).
- `release_use_item(mu: &str)`: Завершить использование предмета.

Функции, отвечающие за состояния ботов:

- `set_state(mu: &str, field: &str, value: bool)`: Установка значения (true / false) для определённого состояния указанного бота.
- `get_state(mu: &str, field: &str) -> bool`: Получение значения определённого состояния у указанного бота.

Функции, доступные при фичи "Auto-Script":

- `current_bot_id() -> i64`: Получение Entity ID текущего бота.
- `current_bot_ping() -> i64`: Получение пинга текущего бота.
- `current_bot_feet_pos() -> Position`: Получение позиции ног текущего бота.
- `current_bot_eye_pos() -> Position`: Получение позиции глаз текущего бота.
- `current_bot_health() -> f64`: Получение здоровья текущего бота.
- `current_bot_satiety() -> i64`: Получение сытости текущего бота.
- `current_bot_profile() -> Profile`: Получение профиля текущего бота.

## Структуры данных

- **Position**
  - x: `f64`
  - y: `f64`
  - z: `f64`

- **Profile**
  - ping: `i64`
  - captcha_caught: `bool`
  - registered: `bool`
  - logined: `bool`
  - group: `&str`
  - health: `i64`
  - password: `&str`
  - email: `&str`

## Что за состояния ботов?

Состояние бота — это значение в виде флага (true / false) для некого диапазона действий (например: атака, ходьба), влияющее на поведение и возможности бота.

Существует всего 2 вида состояний — `is` и `can`. Is-состояния отвечают за текущее положение бота (к примеру, бот сейчас ходит). Can-состояния отвечают за возможное положение бота (к примеру, сможет ли бот атаковать сущности).
Список всех доступных состояний:

- `can_walking`
- `can_sprinting`
- `can_eating`
- `can_drinking`
- `can_attacking`
- `can_looking`
- `can_interacting`
- `is_walking`
- `is_sprinting`
- `is_eating`
- `is_drinking`
- `is_attacking`
- `is_looking`
- `is_interacting`

## Пояснения

- Что означает аргумент `mu: &str` у многих функций? — Даннный аргумент определяет какой бот попадёт под ей влияние, то есть здесь указывается юзернейм бота. Если указать в этом поле `*`, то функция окажет влияние на всех существующих ботов.
- Что означает аргумент `lock: bool` у функций, который взаимодействуют с инвентарём? — Даннный аргумент определяет, можно ли блокировать состояния бота при взаимодействии или же нет.

## Фича "Auto-Script"

Да, это просто обычная фича в разделе _Настройки_, но она имеет особое поведение при включении.

Данная фича автоматически запускает сценарий (который был написан до запуска) для текущего бота, как только тот заспавнится. Если у тебя будет включены фичи **Auto-Register** / **Auto-Login**, то сценарий не запустится сразу, ибо у этих фич более высокий приоретет, сценарий начнёт выполнение только после полного завершения процесса авторизации.

Так же при использовании фичи **Auto-Script** в своём сценарии можно не указывать идентификаторы ботов в аргументах функций, вместо этого просто `""`, ибо явное указание идентификаторов не будет нести какого-то значения в таком случае. Автоматический исполнитель сценария для определённого бота сам захватывает его юзернейм (что является идентификатором) и подставляет его под все нужные функции.

## Примеры сценариев

Отправка 4 сообщений в чат:

```
for i in 0..=3 {
  chat("*", "repeat " + (i + 1)); // Здесь "*" - все боты
  sleep(1.5); // Ожидание 1500 мс
}
```

Простой Anti-AFK:

```
// Да, просто let, в Rhai нету mut переменных
let c = 0;

// Подобные циклы не рекомендуется ставить, ведь
// если в их теле ботам задаются какие-то состояния,
// после ручного выключения они не перестанут быть
// активными. Здесь же с определённым шансом после
// остановки боты всё ещё будут ходить.
while true {
  // Проверка, не выходит ли счётчик
  // за грани массива направлений
  if c > 7 {
    c = 0;
  }

  let directions = [
    "forward",
    "forward-left",
    "forward-right",
    "left",
    "right",
    "backward",
    "backward-right",
    "backward-left"
  ];

  // Запускаем движение по текущему
  // направлению (зависит от счётчика)
  start_walking("*", directions[c]);

  let action_is_enabled = true;

  // В Rhai нету match, поэтому
  // используется конструкция if-else
  if c == 3 {
    set_jumping("*", true);
  } else if c == 6 {
    set_crouching("*", true);
  } else {
    action_is_enabled = false;
  }

  if action_is_enabled {
    sleep(0.5);

    // Остановка действий
    set_jumping("*", false);
    set_crouching("*", false);
  }

  // Создаём паузу на основе счётчика
  let pause = if c % 2 == 0 {
    0.4
  } else {
    1.5
  };

  sleep(pause);

  // Остановка движения всех ботов
  stop_move("*");

  c += 1;
}
```

## Набор стилей

Наборы стилей — это одна из самых интересных фич клиента, ведь с помощью неё можно от и до кастомизировать стили интерфейса.

### Как это работает?

Всё просто, ты создаёшь JSON файл с инструкциями (где в основном цвета, чуть реже значения размерности и силы), после чего загружаешь его в клиент — Фокус, стили поменялись мгновенно!

### Что за инструкции?

Инструкции (в данном контексте) — это пары рода `"key": "value"` (ключ + значение).

### Создание набора стилей

Создать набор стилей довольно просто:

1. Запусти Salarixi (если ты читаешь это не из окна клиента, хах).
2. Создай где-нибудь JSON файл, например `stylekit.json` (главное, чтобы в конце названия было `.json`). 
3. Убедись, что для файла выделены права на запись и чтение (обычно, операционная система Windows или дистрибутивы Linux выделяют нужные права сами при создании файла).
4. Открой созданный файл и напиши в нём `{}`.
5. Далее в этих же скобках можно прописывать инструкции, о них ниже.

### Дополнительно

Перед применением твоего набора стилей клиент проверяет количество совпадений (ключи, которые есть и в целевом наборе стилей и в системе клиента), и он отклонит применение только в том случае, если этих совпадений будет 0 (то есть в файле нету инструкций вовсе). Исходя из этого, если тебе нужно поменять цвет одного элемента, совсем не обязательно вписывать все инструкции, клиент автоматически поставит им значение по умолчанию.

Ключи инструкций могут иметь два формата записи:

- `--KEY`: Полный формат записи (да, как переменная в CSS).
- `KEY`: Сокращённый формат записи, тоже корректный.

# Быстрые задачи

Это не является разделом клиента, просто ещё одна фича :3

## Что это такое?

Быстрые задачи (или же управление ботами с помощью горячих клавиш) — возможность управлять ботами при помощи **горячих клавиш**.
Управлять быстрыми задачами можно только во время **активного процесса**, то есть когда вы запустили ботов на сервер.

## Горячие клавиши

- `Shift + W` — идти вперёд (продолжительность 200мс).
- `Shift + A` — идти влево (продолжительность 200мс).
- `Shift + S` — идти назад (продолжительность 200мс).
- `Shift + D` — идти вправо (продолжительность 200мс).
- `Shift + I + C` — полностью очистить инвентарь.
- `Shift + J` — прыгнуть.
- `Shift + C` — присесть.
- `Shift + Alt + Q` — отключиться от сервера.
- `Shift + G + F` — полёт (изменение velocity по Y на 0.26±5).
- `Shift + G + R` — прыгнуть и поставить под себя блок.
- `Shift + G + C` — построить вокруг себя капсулу из блоков.
- `Shift + U` — объедениться (идти на центральные координаты по X и Z).
- `Shift + T` — повернуть голову на 50 градусов.
- `Shift + Z` — повернуть голову в исходное состояние (0.0, 0.0).
- `Shift + F + C` — сформировать круг (радиус зависит от кол-ва ботов).
- `Shift + F + L` — сформировать линию.
- `Shift + P + S` — остановить работу pathfinder.
